# セットアップ

画面の名前や場所は変わりやすいので、迷ったら出典の公式ドキュメントを見ること。

## Instagram

新しく作ったアプリでは「Instagram ログイン方式」が選べず、**Unified Login（統合ログイン）** だけになっている（2026年11月時点）。ツールの既定はこちら（`IG_LOGIN=unified`、接続先 `graph.facebook.com`）。

前提：
- **プロアカウント**（ビジネス または クリエイター）。個人アカウントなら、Instagram アプリの「アカウントの種類とツール」で切り替える。プロアカウントは非公開にできない
- **ビジネスポートフォリオ**（Meta Business Suite。無料）。作っただけでは書類審査は始まらない
- Facebook ページとの連携は不要

手順：
1. [Meta for Developers](https://developers.facebook.com/) で開発者登録し、アプリを作る（ユースケースは Instagram API）
2. 「API setup with Unified login」を開き、ビジネスポートフォリオをリンクする（なければ「新しいアカウントを作成」）
3. 「新しい設定を作成」で設定（configuration）を作る。アクセストークンは「システムユーザーアクセストークン」、ビジネスアセットは Instagram アカウントだけ（広告アカウントは選ばない）
   - 権限は `instagram_basic` と `instagram_content_publish` を使う。広告（`ads_*`）とコメント（`instagram_manage_comments`）は外す
   - `instagram_manage_messages`（DM）は、ユースケースに必須として入っていて**外せない**。ツールはDMのAPIを呼ばない
   - リダイレクトURLは、自分で使うだけなら仮のURL（`https://localhost/` など）でよい
4. 「役割」タブで、投稿に使う Instagram アカウントに「Instagramテスター」を割り当て、Instagram 側で招待を承認する
5. アカウントを追加し、トークンを生成する
6. Instagram アカウントのIDを `IG_USER_ID`、トークンを `IG_ACCESS_TOKEN` として `.env` に入れる。`IG_API_VERSION` は公式の最新に合わせる
7. `sns-post limit` で、投稿せずに接続を確かめる（読み取りだけ）

注意：
- システムユーザートークンは**期限がない**。そのぶん漏れたときの被害が大きい（DMの権限も付いている）。`.env` 以外に置かず、漏れたかもと思ったら Meta の画面ですぐ無効にして作り直す
- `sns-post refresh-token` は不要（旧 Instagram ログイン方式のトークン用）
- 自分の管理するアカウントだけなら、アプリレビューは不要（未確認。開発モードでテスターのアカウントに投稿できるかを確かめる）。他人のアカウントを多数つなぐ場合は、アプリレビューとビジネス認証（Advanced Access）が必要
- 画像は **JPEG** で、Meta のサーバーが取りに来られる **公開URL** に置く（認証が必要なURLや、プライベートリポジトリのURLは使えない）
- 上限：24時間で100投稿（カルーセルは1投稿）。古い解説にある「25」「50」は昔の値（公式ページの中でもカルーセルの節に「50」と書かれた所が残っている。実際の残りは `sns-post limit` で確かめる）
- 複数枚（カルーセル）：1枚ずつ `is_carousel_item=true` のコンテナを作り、`media_type=CAROUSEL` と `children`（コンテナIDをカンマ区切り）でまとめてから公開する。**20枚まで**。キャプションはまとめたコンテナにつける（1枚ずつのコンテナでは使えない）。画像は1枚目に合わせて切り取られる（既定は 1:1）。公式に下限の記載はないが、このツールでは2枚以上（1枚なら `image_url`）。実際のアカウントでの投稿は**未確認**

旧 Instagram ログイン方式（古いアプリで「API setup with Instagram business login」がある場合）：
- 権限は `instagram_business_basic` と `instagram_business_content_publish`。`.env` に `IG_LOGIN=instagram` を書く（接続先 `graph.instagram.com`）
- トークンの有効期間は60日。切れる前に `sns-post refresh-token` で更新する

## X

1. [X Developer Console](https://developer.x.com/) でアプリを作る
2. User authentication settings で、アプリの権限（App permissions）を **Read and write** にする（DM の権限は不要）。アプリの種類は「Web App, Automated App or Bot」。Callback URL は必須なので、自分で使うだけなら `http://localhost:8000/` などでよい
3. API Key と Secret、Access Token と Secret を作り、`.env` の `X_API_KEY` `X_API_SECRET` `X_ACCESS_TOKEN` `X_ACCESS_TOKEN_SECRET` に入れる
   - 権限を変えたあとに、Access Token を作り直すこと（古いものは権限が古いまま）
4. 従量課金のクレジットを購入し、**支出の上限**（spend cap）を低く設定する

注意：
- 2026年2月から従量課金が標準。目安は通常の投稿 約0.015ドル、リンク付き 約0.20ドル
- フォロー・いいね・引用投稿は、従量課金プランでは使えない
- 文字数は「重みつき」で280まで。日本語・絵文字は1文字=2、URLは長さにかかわらず23（`sns-post check` で確認できる）
- 数字は変わるので、公式の料金ページで確認する

## 画像の置き場所（クラウドストレージ）

Instagram は、**公開されているサーバーにある JPEG** の URL からしか画像を取れない（Meta のサーバーが投稿の試行のときに画像を取りに来る。JPEG 以外、MPO・JPS などの拡張 JPEG も不可）。そこで、画像は**非公開のバケット**に置き、投稿の直前に**期限つきURL（署名付きURL）**を作って Meta に渡す。投稿ファイルには URL ではなく、バケット内の名前を `image_key: images/xxxx.jpg` と書く（`image_url` を書けば、従来どおりその URL を使う）。

使えるのは S3 互換のストレージ（Cloudflare R2・AWS S3 など）。Cloudflare R2 の場合（2026年11月に公式で確認）：

1. Cloudflare でバケットを作る（公開設定にはしない）
2. R2 の API トークン（Access Key ID と Secret Access Key）を作る。権限は、そのバケットだけの読み書きにする
3. `pip install -e ".[storage]"`
4. `.env` に `STORAGE_BUCKET`・`STORAGE_ACCESS_KEY_ID`・`STORAGE_SECRET_ACCESS_KEY`・`STORAGE_ENDPOINT_URL`（`https://<アカウントID>.r2.cloudflarestorage.com`）を入れる。`STORAGE_REGION` は `auto` のまま

R2 の数字（標準ストレージ）：

| 項目 | 値 |
|---|---|
| 保存 | 0.015ドル / GB・月 |
| 書き込み系の操作（Class A） | 4.50ドル / 100万回 |
| 読み取り系の操作（Class B） | 0.36ドル / 100万回 |
| 外部への転送（egress） | 無料 |
| 毎月の無料分 | 10 GB・月、Class A 100万回、Class B 1,000万回 |

- 署名付きURLの有効期限は1秒〜7日。ツールは**1時間**で作る（投稿の直前に作るので十分）
- 署名付きURLは S3 API のドメイン（`<アカウントID>.r2.cloudflarestorage.com`）でだけ使える。独自ドメインでは使えない
- 画像1枚は 8MB までに、ツール側で制限している。これはツール側の安全のための上限で、Instagram 側のサイズ上限は公式のこのページには書かれておらず**未確認**
- **未確認：** Meta が署名付きURLから画像を取れるか（URL に認証の情報が付くため）。実際のアカウントで確かめるまで、この方式は「動く想定」にすぎない。うまくいかないときは、期限つきではない公開URLに切り替える
- 画像（JPEG）は、バケットから消さない限り残る。投稿後の整理は、バケットの「オブジェクトのライフサイクル」で自動で消す設定ができる

## 定期実行（画面を開かずに、時刻が来たら投稿する）

`sns-post web --publish` を開いている間は、画面が1分ごとに投稿する。画面を開かずに動かしたいときは、PC の仕組みで `run-due --publish` を数分ごとに呼ぶ。

呼ぶコマンド（10分ごとの例）：

```
sns-post -C <このフォルダ> run-due --publish --log posts/run.log
```

- `-C`：このフォルダ（`.env` と `posts/` があるところ）で動かす。スケジューラはほかの場所から呼ぶので必須
- `--log`：結果を日時つきで `posts/run.log` に追記する（画面がないので、あとで見返す用）。本文は書かない。何もなかった回は書かない
- 画面（`web --publish`）と同時に動いても、ロック（`posts/.publish.lock`）で順番に投稿するので二重投稿しない。重なった回は `[エラー] ほかの場所で投稿中です` と記録され、次の回に投稿される
- `sns-post` の場所は、Windows なら `where sns-post`、Mac なら `which sns-post` で調べて、フルパスで書く

### Windows（タスクスケジューラ）

**未確認：** 実際の PC でタスクスケジューラに登録して動かすのは、まだ試していない（`--dry-run` での登録・`--publish` での実際の投稿とも）。確かめるときは、`sns-post schedule --install --dry-run --every 1` で登録し、1分ごとに動いて `posts/run.log` に `[下見]` が出ること、「前回の実行結果」が 0 になることを見る。

かんたんな方法：このフォルダで次を実行する。

1. `sns-post schedule` … 登録するコマンドを表示するだけ（まだ登録しない）
2. `sns-post schedule --install --dry-run` … 下見だけで登録して、10分ほど待ち、`posts\run.log` に `[下見]` が出るか確かめる（時刻が来た予約があるときだけ書かれる）
3. `sns-post schedule --install` … `--publish` つきで登録し直す（同じ名前「sns-post」で上書き）
4. 状態は `sns-post schedule --status`、消すときは `sns-post schedule --remove`。間隔は `--every 5` のように変えられる（1〜1439分）

- 黒い画面が出ないよう、`python.exe` の代わりに `pythonw.exe` で動かす
- 登録するコマンドは約260文字まで（schtasks の /TR は公式に262文字まで。1文字余裕をみて261で止める）。長すぎるときは止まるので、フォルダを `C:\sns-post` などの短い場所に移す
- 登録したタスクは「AC電源のときだけ動く」設定になる（`sns-post schedule --status` で `Stop On Battery Mode, No Start On Batteries` と出ることを確認）。ノートPCを電池で動かしている間は投稿されない。電池でも動かしたいときは、タスクスケジューラの画面で「sns-post」の「条件」タブを変える

自分で schtasks を書く場合は、コマンドプロンプトで1回だけ実行する（パスは自分のものに置き換える）：

```
schtasks /Create /TN "sns-post" /SC MINUTE /MO 10 /TR "\"C:\パス\Scripts\sns-post.exe\" -C \"C:\パス\sns-toukou-automation\" run-due --publish --log posts\run.log"
```

- 止める：`schtasks /Change /TN "sns-post" /DISABLE`、消す：`schtasks /Delete /TN "sns-post"`
- 動いたかは、タスクスケジューラの「前回の実行結果」（0 なら成功、1 ならエラー）と `posts\run.log` で見る
- 実行のたびに黒い画面が一瞬出ることがある（未確認）。気になるときは、タスクのプロパティで「ユーザーがログオンしているかどうかにかかわらず実行する」にする

### Mac・Linux（cron）※未確認

`crontab -e` で1行足す：

```
*/10 * * * * /パス/bin/sns-post -C /パス/sns-toukou-automation run-due --publish --log posts/run.log
```

### 気をつけること

- **PC がスリープ・電源オフの間は投稿されない。** 次に動いたときに、時刻を過ぎた予約をまとめて投稿する（遅れて出る）。「今日のランチ」のような時間の決まった投稿は、PC をつけたあとに `sns-post run-due`（下見）で何が出るかを先に確かめる
- まずは `--publish` なし（下見）で登録して、`posts/run.log` に `[下見]` が出ることを確かめてから `--publish` をつける

### GitHub Actions を使わない理由

- 投稿の記録（`results:`）を GitHub に push し直す必要があり、投稿のあと push に失敗すると、次の回に**二重投稿**するおそれがある
- 定期実行（schedule）は混んでいると遅れたり、飛ばされたりすることがある（GitHub の公式ドキュメント）
- トークンを GitHub の Secrets にも置くことになる

## X の文面の下書き（生成AI・任意）

Instagram の本文から、X の重みつき280文字に収まる文面（`x_text`）の下書きを生成AIに作らせる機能。**投稿はしない。** 下書きは人が読んで直してから使う。

1. `pip install -e ".[llm]"`（Gemini と Claude の公式 SDK：`google-genai`・`anthropic`）
2. API キーを作って `.env` に入れる。どちらか一方でよい
   - Gemini：Google AI Studio で API キーを作り、`GEMINI_API_KEY` に入れる（`LLM_PROVIDER=gemini`。既定）
   - Claude：Claude Console で API キーを作り、`ANTHROPIC_API_KEY` に入れる（`LLM_PROVIDER=claude`）
3. モデルは既定で `gemini-3.8-flash` / `claude-opus-5-5`。変えるときは `GEMINI_MODEL` / `CLAUDE_MODEL`
4. 使い方
   - コマンド：`sns-post draft-x <投稿ファイル>` で下書きを表示する。`--write` をつけたときだけ、そのファイルの `x_text` に書き込む
   - 予約画面：「Xだけ別の文面」の下の「AIで下書き」を押すと、入力欄に下書きが入る（`予約する` を押すまでファイルにはならない）。キーが `.env` にないときは、このボタンは出ない

### 決めていること

| 決めたこと | 理由 |
|---|---|
| 文字数は生成AIではなくツールが数える。超えたら「何文字だったか」を伝えて最大3回作り直させる | 生成AIは X の重みつきの数え方（日本語=2）を正確に数えられないため |
| 本文の URL が下書きから消えたら知らせる。事実（日時・場所・値段）を変えない・足さないよう指示する | 宣伝の投稿で事実が変わると、お店が困るため。それでも最後は人が確かめる |
| 下書きは投稿しない。`--write` も、一部でも投稿済みの予約には書かない。書く直前にファイルが変わっていないかを、投稿中の目印（ロック）を取ってから確かめる | 二重投稿や記録の食い違いを起こさないため（予約画面の変更と同じ決まり） |
| Gemini と Claude を `.env` で切り替えられる（`llm.py` の `TextModel`） | SNS の API と同じく差し替えられる形にして、テストでは偽のモデルを使うため |
| Claude は、断られたとき（`refusal`）にサーバー側で別のモデルに引き継ぐ設定（`fallbacks: "default"`）をつけている | Anthropic の SDK の推奨。断られたら、その旨を表示して止まる |
| Gemini が混んでいる（`503`）・回数の上限（`429`）のときだけ、2秒・5秒あけて送り直す（最大3回）。ほかのエラー（キー違いの `400`・`401`・`403` など）は送り直さずに止める | 「一時的なので、あとで試して」というエラーで、毎回人が打ち直さなくてよいように。送り直しても下書きを作るだけで、投稿はしない |
| Gemini の返事は60秒まで待つ。来なければエラーにして止める（`HttpOptions(timeout=...)`。単位はミリ秒） | 返事が来ないまま、画面が止まり続けないように |

- 料金：下書きを1回作るたびに、選んだモデルの料金がかかる（作り直すと、その回数分）。金額は変わるので、使う前に各社の料金ページで確かめる
- 実際の API キーでの動作は**未確認**（偽のモデル・偽の SDK クライアントでのみテスト）
  - 2026-11-17：Gemini（無料枠のキー）で試したところ、キーは通ったが、何度か `503 UNAVAILABLE`（混雑）が返って下書きはまだ作れていない。これを受けて、上の「送り直し」と「60秒で止める」を足した
- 料金：無料枠（Free tier）のキーなら請求は来ない（使える回数に上限がある）。Google の FAQ の写しでは、400・500番台のエラーは料金がかからない（回数には数える）とあるが、503 でも請求されたという報告もあり、はっきりは**未確認**
- Gemini のモデル名は、Google の公式ページを開けない環境で調べたため、検索結果の表示（`gemini-3.8-flash` が stable）で確かめた。**公式ページで直接は未確認**
