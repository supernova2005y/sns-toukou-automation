# 仕組みの説明（自分で説明できるようになるためのメモ）

このツールを人に説明するときのための資料。コードを1行ずつ追わなくても、「何が・どの順で・なぜそうなっているか」が言えるようにまとめた。
ファイル名は `src/sns_post/` の中のもの。

---

## 1. 30秒で説明すると

> お店のSNS担当が、Markdownで投稿を書いてフォルダに置いておくと、時刻が来たものを Instagram と X に自動で投稿するツールです。
> 誤投稿が怖いので、ふだんは「何が投稿されるか」を表示するだけで、`--publish` をつけたときだけ本当に投稿します。
> 途中で失敗しても、成功した分を記録しているので、やり直しても二重には投稿しません。

---

## 2. 1回の実行で起きること

`sns-post run-due --publish` を実行したときの流れ。

1. **設定を読む**（`config.py`）
   `.env` からトークンなどを読み込む。足りなければ、何が足りないかを表示して止まる
2. **投稿ファイルを全部読む**（`posts.py` の `load_posts`）
   `posts/queue/` の `.md` を1つずつ開き、`---` で挟まれた上の部分（設定）と下の部分（本文）に分ける
3. **書き方をチェックする**（`posts.py` の `validate`）
   - 投稿時刻にタイムゾーンがあるか（ないと日本時間か世界標準時か分からない）
   - Instagram なら https の画像URLがあるか、キャプション2,200文字・ハッシュタグ30個以内か
   - X なら文字数が280以内か（日本語は1文字=2、URLは23で数える。X 本体と同じ数え方）
   1つでもおかしければ、どのファイルの何が悪いかを表示して止まる
4. **時刻が来たものを選ぶ**（`runner.py` の `run_due`）
   投稿時刻が「今」より前で、まだ投稿していない先（`results:` にない先）だけを対象にする
5. **投稿する**
   - Instagram（`instagram.py`）：3段階。①「この画像とこの文章で投稿したい」と予約（コンテナ作成）→ ②Instagram 側の準備ができるまで2秒ごとに確認 → ③公開
   - X（`x.py`）：文章を1回送るだけ
6. **成功したらすぐ記録する**
   成功した先の投稿IDを、そのファイルの `results:` に書き込む。全部の先に投稿できたら `posts/done/` に移す

## 3. よく聞かれそうな「なぜ」

**なぜ既定が下見（dry-run）なの？**
お店のアカウントで間違った投稿をすると、消しても見た人の記憶には残る。うっかり実行しても何も起きないようにして、本当に投稿するときだけ `--publish` をつける形にした。

**二重投稿をどう防いでいるの？**
Instagram には成功して X で失敗した、のように途中で止まることがある。成功した先はその場でファイルに記録するので、もう一度実行しても X だけを投稿し直す。テスト `test_partial_failure_does_not_repost_on_retry` で確かめている。

**なぜデータベースを使わずファイルなの？**
投稿の数は1日に数件で、データベースは大げさ。ファイルなら中身を人が読めて、Git で「いつ誰が何を変えたか」も残る。担当が変わっても引き継ぎやすい。

**トークン（パスワードのようなもの）はどう守っているの？**
- `.env` にだけ置き、GitHub には上げない（`.gitignore`）
- Instagram へはURLではなくヘッダーで渡す（URLはエラー表示やログに残りやすいため）
- 設定を表示しても、トークンの欄は出ないようにした（`field(repr=False)`）
- トークンを更新したときも、画面には出さずに `.env` へ直接書き込む

**テストで本物の Instagram や X に投稿していないの？**
していない。API を呼ぶ部分を「偽物」に差し替えて、どのURLに何を送ったか・失敗したら何が起きるかを確かめている（24件）。GitHub に push すると、GitHub Actions で自動で全部のテストが走る。本物のアカウントでの確認は、テスト用アカウントで別にやる。

**なぜ公式APIだけなの？ 自動いいねとかはしないの？**
非公式のツールや自動いいね・フォローは規約違反になりやすく、お店のアカウントが止められるおそれがある。お店にとって一番困るのはアカウントを失うことなので、そこはやらないと決めた。

**AIで作ったんでしょ？ あなたは何をしたの？**
（ここは自分の言葉で答える。例えば：どんな困りごとを解決したいかを決めたこと、「誤投稿が怖い」「担当がいないと止まる」をどう仕組みで防ぐかを決めたこと、AIが書いたものをテストで確かめたこと、など）

## 5. 自分で確かめるための練習

上から順にやると、仕組みが手で分かる。

1. `examples/` のサンプルを `posts/queue/` にコピーして `sns-post check`
2. サンプルの `+09:00` を消してもう一度 `check` → タイムゾーンのエラーが出るのを見る
3. `sns-post run-due --now 2026-11-02T00:00:00+09:00` → 下見で「何が投稿されるか」が出るのを見る
4. `x_text:` の行を消し、本文を日本語141文字にして `check` → X の文字数エラー（282/280）が出るのを見る（`x_text` があると X にはそちらが使われるので、消してから試す）
5. `pytest -q` → 全部のテストが通るのを見る
