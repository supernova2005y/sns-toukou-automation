# セットアップ

画面の名前や場所は変わりやすいので、迷ったら出典の公式ドキュメントを見ること。

## Instagram

新しく作ったアプリでは「Instagram ログイン方式」が選べず、**Unified Login（統合ログイン）** だけになっている（2026年11月時点）。ツールの既定はこちら（`IG_LOGIN=unified`、接続先 `graph.facebook.com`）。

前提：
- **プロアカウント**（ビジネス または クリエイター）。個人アカウントなら、Instagram アプリの「アカウントの種類とツール」で切り替える。プロアカウントは非公開にできない
- **ビジネスポートフォリオ**（Meta Business Suite。無料）。作っただけでは書類審査は始まらない
- Facebook ページとの連携は不要

手順：
1. [Meta for Developers](https://developers.facebook.com/) で開発者登録し、アプリを作る（ユースケースは Instagram API）
2. 「API setup with Unified login」を開き、ビジネスポートフォリオをリンクする（なければ「新しいアカウントを作成」）
3. 「新しい設定を作成」で設定（configuration）を作る。アクセストークンは「システムユーザーアクセストークン」、ビジネスアセットは Instagram アカウントだけ（広告アカウントは選ばない）
   - 権限は `instagram_basic` と `instagram_content_publish` を使う。広告（`ads_*`）とコメント（`instagram_manage_comments`）は外す
   - `instagram_manage_messages`（DM）は、ユースケースに必須として入っていて**外せない**。ツールはDMのAPIを呼ばない
   - リダイレクトURLは、自分で使うだけなら仮のURL（`https://localhost/` など）でよい
4. 「役割」タブで、投稿に使う Instagram アカウントに「Instagramテスター」を割り当て、Instagram 側で招待を承認する
5. アカウントを追加し、トークンを生成する
6. Instagram アカウントのIDを `IG_USER_ID`、トークンを `IG_ACCESS_TOKEN` として `.env` に入れる。`IG_API_VERSION` は公式の最新に合わせる
7. `sns-post limit` で、投稿せずに接続を確かめる（読み取りだけ）

注意：
- システムユーザートークンは**期限がない**。そのぶん漏れたときの被害が大きい（DMの権限も付いている）。`.env` 以外に置かず、漏れたかもと思ったら Meta の画面ですぐ無効にして作り直す
- `sns-post refresh-token` は不要（旧 Instagram ログイン方式のトークン用）
- 自分の管理するアカウントだけなら、アプリレビューは不要（未確認。開発モードでテスターのアカウントに投稿できるかを確かめる）。他人のアカウントを多数つなぐ場合は、アプリレビューとビジネス認証（Advanced Access）が必要
- 画像は **JPEG** で、Meta のサーバーが取りに来られる **公開URL** に置く（認証が必要なURLや、プライベートリポジトリのURLは使えない）
- 上限：24時間で100投稿（カルーセルは1投稿）。古い解説にある「25」「50」は昔の値

旧 Instagram ログイン方式（古いアプリで「API setup with Instagram business login」がある場合）：
- 権限は `instagram_business_basic` と `instagram_business_content_publish`。`.env` に `IG_LOGIN=instagram` を書く（接続先 `graph.instagram.com`）
- トークンの有効期間は60日。切れる前に `sns-post refresh-token` で更新する

## X

1. [X Developer Console](https://developer.x.com/) でアプリを作る
2. User authentication settings で、アプリの権限（App permissions）を **Read and write** にする（DM の権限は不要）。アプリの種類は「Web App, Automated App or Bot」。Callback URL は必須なので、自分で使うだけなら `http://localhost:8000/` などでよい
3. API Key と Secret、Access Token と Secret を作り、`.env` の `X_API_KEY` `X_API_SECRET` `X_ACCESS_TOKEN` `X_ACCESS_TOKEN_SECRET` に入れる
   - 権限を変えたあとに、Access Token を作り直すこと（古いものは権限が古いまま）
4. 従量課金のクレジットを購入し、**支出の上限**（spend cap）を低く設定する

注意：
- 2026年2月から従量課金が標準。目安は通常の投稿 約0.015ドル、リンク付き 約0.20ドル
- フォロー・いいね・引用投稿は、従量課金プランでは使えない
- 文字数は「重みつき」で280まで。日本語・絵文字は1文字=2、URLは長さにかかわらず23（`sns-post check` で確認できる）
- 数字は変わるので、公式の料金ページで確認する

## 定期実行（画面を開かずに、時刻が来たら投稿する）

`sns-post web --publish` を開いている間は、画面が1分ごとに投稿する。画面を開かずに動かしたいときは、PC の仕組みで `run-due --publish` を数分ごとに呼ぶ。

呼ぶコマンド（10分ごとの例）：

```
sns-post -C <このフォルダ> run-due --publish --log posts/run.log
```

- `-C`：このフォルダ（`.env` と `posts/` があるところ）で動かす。スケジューラはほかの場所から呼ぶので必須
- `--log`：結果を日時つきで `posts/run.log` に追記する（画面がないので、あとで見返す用）。本文は書かない。何もなかった回は書かない
- 画面（`web --publish`）と同時に動いても、ロック（`posts/.publish.lock`）で順番に投稿するので二重投稿しない。重なった回は `[エラー] ほかの場所で投稿中です` と記録され、次の回に投稿される
- `sns-post` の場所は、Windows なら `where sns-post`、Mac なら `which sns-post` で調べて、フルパスで書く

### Windows（タスクスケジューラ）※未確認

コマンドプロンプトで1回だけ実行する（パスは自分のものに置き換える）：

```
schtasks /Create /TN "sns-post" /SC MINUTE /MO 10 /TR "\"C:\パス\Scripts\sns-post.exe\" -C \"C:\パス\sns-toukou-automation\" run-due --publish --log posts\run.log"
```

- 止める：`schtasks /Change /TN "sns-post" /DISABLE`、消す：`schtasks /Delete /TN "sns-post"`
- 動いたかは、タスクスケジューラの「前回の実行結果」（0 なら成功、1 ならエラー）と `posts\run.log` で見る
- 実行のたびに黒い画面が一瞬出ることがある（未確認）。気になるときは、タスクのプロパティで「ユーザーがログオンしているかどうかにかかわらず実行する」にする

### Mac・Linux（cron）※未確認

`crontab -e` で1行足す：

```
*/10 * * * * /パス/bin/sns-post -C /パス/sns-toukou-automation run-due --publish --log posts/run.log
```

### 気をつけること

- **PC がスリープ・電源オフの間は投稿されない。** 次に動いたときに、時刻を過ぎた予約をまとめて投稿する（遅れて出る）。「今日のランチ」のような時間の決まった投稿は、PC をつけたあとに `sns-post run-due`（下見）で何が出るかを先に確かめる
- まずは `--publish` なし（下見）で登録して、`posts/run.log` に `[下見]` が出ることを確かめてから `--publish` をつける

### GitHub Actions を使わない理由

- 投稿の記録（`results:`）を GitHub に push し直す必要があり、投稿のあと push に失敗すると、次の回に**二重投稿**するおそれがある
- 定期実行（schedule）は混んでいると遅れたり、飛ばされたりすることがある（GitHub の公式ドキュメント）
- トークンを GitHub の Secrets にも置くことになる
