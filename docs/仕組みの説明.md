# 仕組みの説明（自分で説明できるようになるためのメモ）

このツールを人に説明するときのための資料。コードを1行ずつ追わなくても、「何が・どの順で・なぜそうなっているか」が言えるようにまとめた。
ファイル名は `src/sns_post/` の中のもの。

---

## 1. 30秒で説明すると

> 小さなお店のSNS担当が、Markdownで投稿を書いてフォルダに置いておくと、時刻が来たものを Instagram と X に自動で投稿するツールです。
> 誤投稿が怖いので、ふだんは「何が投稿されるか」を表示するだけで、`--publish` をつけたときだけ本当に投稿します。
> 途中で失敗しても、成功した分を記録しているので、やり直しても二重には投稿しません。

---

## 2. 1回の実行で起きること

`sns-post run-due --publish` を実行したときの流れ。

1. **設定を読む**（`config.py`）
   `.env` からトークンなどを読み込む。足りなければ、何が足りないかを表示して止まる
2. **投稿ファイルを全部読む**（`posts.py` の `load_posts`）
   `posts/queue/` の `.md` を1つずつ開き、`---` で挟まれた上の部分（設定）と下の部分（本文）に分ける
3. **書き方をチェックする**（`posts.py` の `validate`）
   - 投稿時刻にタイムゾーンがあるか（ないと日本時間か世界標準時か分からない）
   - Instagram なら https の画像URLがあるか、キャプション2,200文字・ハッシュタグ30個以内か
   - X なら文字数が280以内か（日本語は1文字=2、URLは23で数える。X 本体と同じ数え方）
   1つでもおかしければ、どのファイルの何が悪いかを表示して止まる
4. **時刻が来たものを選ぶ**（`runner.py` の `run_due`）
   投稿時刻が「今」より前で、まだ投稿していない先（`results:` にない先）だけを対象にする
5. **投稿する**
   - Instagram（`instagram.py`）：3段階。①「この画像とこの文章で投稿したい」と予約（コンテナ作成）→ ②Instagram 側の準備ができるまで2秒ごとに確認 → ③公開
   - X（`x.py`）：文章を1回送るだけ
6. **成功したらすぐ記録する**
   成功した先の投稿IDを、そのファイルの `results:` に書き込む。全部の先に投稿できたら `posts/done/` に移す

---

### 予約画面（`sns-post web`、`web.py`）

画面の基本は「投稿ファイルを書く係」。投稿の仕組み（上の1〜6）には手を入れていない。
`sns-post web --publish` で起動したときだけ、画面からも投稿する（`publisher.py`）。

- 「予約する」を押すと、上の 3 と同じチェック（`validate`）を通してから `posts/queue/` に .md を1つ書く。過ぎた日時は受け付けない
- 一覧は `posts/queue/` と `posts/done/` を読んで、予約中・時刻を過ぎた予約・済み・読めないファイル、に分けて返す
- 標準ライブラリだけで動くので、追加でインストールするものはない
- 認証がないので、既定では自分のPC（127.0.0.1）からしか開けない。別のサイトから勝手に予約を書き込まれないよう、JSON で、同じ画面から送られたものだけ受け付ける
- 投稿モード（`--publish`）では「今すぐ投稿」と、時刻が来た予約の自動投稿（1分ごと）をする。中身は `run-due --publish` と同じ `run_due` を呼ぶだけなので、成功した先の記録・done/ への移動・二重投稿の防止もそのまま効く
- 投稿モードは自分のPC（127.0.0.1）でしか起動できない。認証のない画面から、同じWi-Fiの誰でも投稿できてしまうため
- 画面・自動投稿・コマンドの `run-due --publish` が同時に動かないよう、投稿の間だけ `posts/.publish.lock` を置く。15分より古いロックは、落ちた処理の残りとみなして取り直す
- 「今すぐ投稿」は保存済みの内容を投稿する。入力を変えたまま押せないようにして、画面とファイルの食い違いを防いでいる

## 3. よく聞かれそうな「なぜ」

**なぜ既定が下見（dry-run）なの？**
お店のアカウントで間違った投稿をすると、消しても見た人の記憶には残る。うっかり実行しても何も起きないようにして、本当に投稿するときだけ `--publish` をつける形にした。

**二重投稿をどう防いでいるの？**
Instagram には成功して X で失敗した、のように途中で止まることがある。成功した先はその場でファイルに記録するので、もう一度実行しても X だけを投稿し直す。テスト `test_partial_failure_does_not_repost_on_retry` で確かめている。

**なぜデータベースを使わずファイルなの？**
投稿の数は1日に数件で、データベースは大げさ。ファイルなら中身を人が読めて、Git で「いつ誰が何を変えたか」も残る。担当が変わっても引き継ぎやすい。

**トークン（パスワードのようなもの）はどう守っているの？**
- `.env` にだけ置き、GitHub には上げない（`.gitignore`）
- Instagram へはURLではなくヘッダーで渡す（URLはエラー表示やログに残りやすいため）
- 設定を表示しても、トークンの欄は出ないようにした（`field(repr=False)`）
- トークンを更新したときも、画面には出さずに `.env` へ直接書き込む

**画面から投稿して、誤投稿しないの？**
既定の `sns-post web` は今までどおり投稿しない。`--publish` をつけて起動したときだけ投稿モードになり、画面の上に「投稿モード」と出る。「今すぐ投稿」は確認ダイアログを通してから。投稿の処理は `run_due` の1か所だけなので、二重投稿を防ぐ仕組みも増やしていない。

**テストで本物の Instagram や X に投稿していないの？**
していない。API を呼ぶ部分を「偽物」に差し替えて、どのURLに何を送ったか・失敗したら何が起きるかを確かめている（153件。生成AIも偽物に差し替え）。GitHub に push すると、GitHub Actions で自動で全部のテストが走る。本物のアカウントでの確認は、テスト用アカウントで別にやる。

**生成AIはどう組み込んだの？**（`draft.py`・`llm.py`）
- 困りごと：Instagram の本文をそのまま X に出すと、日本語は1文字=2文字分なので、141〜280文字の日本語でも投稿の直前に失敗する。毎回手で縮めるのは手間
- やること：本文から、X の280文字に収まる文面の下書きを生成AIに作らせる。**投稿はしない**（画面の入力欄に入れるか、`--write` でファイルの `x_text` に書くだけ）
- 生成AIの苦手はツールで補う：文字数は生成AIではなくツールが X と同じ数え方で数え、超えたら「何文字だった」と伝えて最大3回作り直させる。本文の URL が消えたら知らせる
- Gemini と Claude を `.env` の `LLM_PROVIDER` で切り替えられる。SNS の API と同じく「差し替えられる形」（`TextModel`）にしたので、テストでは偽のモデルを使える
- 二重投稿の仕組みは壊さない：一部でも投稿済みの予約には書かない。書く直前に投稿中の目印（ロック）を取り、ファイルが変わっていないかを確かめる
- 作るものと使う生成AI（X の文面の下書き、Gemini と Claude の差し替え）は自分で選んだ

**なぜ公式APIだけなの？ 自動いいねとかはしないの？**
非公式のツールや自動いいね・フォローは規約違反になりやすく、お店のアカウントが止められるおそれがある。お店にとって一番困るのはアカウントを失うことなので、そこはやらないと決めた。

**AIで作ったんでしょ？ あなたは何をしたの？**
- 小さなお店の SNS 運用の困りごと（毎回の投稿の手間、担当者がいないと止まること）を聞いて、作るものを決めた
- 既存の手段を調べた。Instagram・X それぞれの公式の予約機能はあるが、複数の SNS にまたがって一度に予約する仕組みは見つけられなかった（網羅的な調査ではない）
- 入力画面と確認画面の構成を考えた（予約画面）。使い心地の作り込みは、これから
- コードは生成AI（Claude）が書いた。自分は、仕様の整理、守るルール（公式APIだけ・既定は下見・二重投稿しない）の決定、テスト用アカウントでの動作確認を担当した

## 5. 自分で確かめるための練習

上から順にやると、仕組みが手で分かる。

1. `examples/` のサンプルを `posts/queue/` にコピーして `sns-post check`
2. サンプルの `+09:00` を消してもう一度 `check` → タイムゾーンのエラーが出るのを見る
3. `sns-post run-due --now 2026-11-02T00:00:00+09:00` → 下見で「何が投稿されるか」が出るのを見る
4. `x_text:` の行を消し、本文を日本語141文字にして `check` → X の文字数エラー（282/280）が出るのを見る（`x_text` があると X にはそちらが使われるので、消してから試す）
5. `pytest -q` → 全部のテストが通るのを見る
