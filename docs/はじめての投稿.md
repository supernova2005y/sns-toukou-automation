# はじめての投稿まで

このツールを初めて使う人が、**テスト用の Instagram アカウントに1件投稿するまで**の流れです。
細かい操作は [`セットアップ.md`](セットアップ.md) に書いてあるので、ここでは「何を・どの順で・どこでつまずきやすいか」だけを並べます。

- かかる時間は書いていません（人によって大きく違い、測っていないため）
- Meta・X の画面の名前や場所は変わりやすいです。迷ったら、下の「読んでおく公式ドキュメント」を見てください
- 最初は、必ず**自分のテスト用アカウント**で試してください

---

## 全体の流れ

- [ ] 1. 認証情報なしで、下見モードで動かす
- [ ] 2. Instagram 側の準備（プロアカウント・ビジネスポートフォリオ）
- [ ] 3. Meta のアプリを作って、トークンを `.env` に入れる
- [ ] 4. 接続を確かめる（投稿はしない）
- [ ] 5. テスト投稿を1件する
- [ ] 6. （任意）X・定期実行・画像の置き場所・生成AIの下書き

---

## 1. 下見モードで動かす（認証情報なし）

README の「[はじめ方](../README.md#はじめ方)」のとおりに進めます。必要なのは Python 3.10 以上と Git です。

- `pytest` がすべて通る
- `sns-post check` で見本の予約が「書き方に問題なし」と出る
- `sns-post web` で http://localhost:8000/ が開き、画面の上に「下見モード」と出る

ここまでできれば、ツール側の準備は終わりです。この段階では、どこにも投稿されません。

## 2. Instagram 側の準備

- **プロアカウント**（ビジネス または クリエイター）にする。個人アカウントなら、Instagram アプリの「アカウントの種類とツール」で切り替える
  - プロアカウントは非公開（鍵アカ）にできません。テスト用のアカウントを別に作ると安心です
- **ビジネスポートフォリオ**（Meta Business Suite。無料）を用意する。次の手順のアプリ作成の途中でも作れます
- Facebook ページとの連携は要りません

## 3. Meta のアプリを作って、トークンを `.env` に入れる

詳しい手順は [`セットアップ.md` の「Instagram」](セットアップ.md#instagram)。流れだけ書くと、次のとおりです。

1. Meta for Developers で開発者登録をして、アプリを作る（ユースケースは Instagram API）
2. 「API setup with Unified login」で、ビジネスポートフォリオをリンクする
3. 設定（configuration）を作る。権限は `instagram_basic` と `instagram_content_publish`
4. 投稿に使う Instagram アカウントを「Instagramテスター」にして、Instagram 側で招待を承認する
5. トークンを作り、`.env` に入れる

```bash
cp .env.example .env
# .env を開いて IG_USER_ID と IG_ACCESS_TOKEN を入れる（IG_LOGIN=unified のまま）
```

- トークンは `.env` 以外（チャット・メモ・スクリーンショット・GitHub）に置かないでください。このトークンは期限がなく、漏れたときの被害が大きいです。漏れたかもと思ったら、Meta の画面ですぐ無効にして作り直します

## 4. 接続を確かめる（投稿はしない）

```bash
sns-post limit
```

24時間の投稿上限の使用状況が出れば、トークンとアカウントIDは合っています（読み取りだけで、投稿はしません）。エラーが出たら、`IG_USER_ID`・`IG_ACCESS_TOKEN`・`IG_API_VERSION` を見直します。

## 5. テスト投稿を1件する

1. 画像を用意する。**公開されている URL の JPEG** が必要です（Meta のサーバーが取りに来るため。PNG・SVG やログインが要る URL は使えません）
   - 試すだけなら、Wikimedia Commons などの、自由に使えるライセンスの JPEG 画像の URL で足ります
   - 自分の写真を使うときは、画像の置き場所の設定が必要です（[`セットアップ.md` の「画像の置き場所」](セットアップ.md#画像の置き場所クラウドストレージ)）
2. `posts/queue/` に投稿ファイルを置く。見本（`examples/2099-01-01_1200_サンプル.md`）をコピーして、次のところを書き換えます
   - `publish_at`：今より少し前の時刻（タイムゾーン `+09:00` つき）。過ぎていると、次の実行で投稿されます
   - `targets: [instagram]`（X をまだ用意していないなら、instagram だけにする）
   - `image_url`：1 の画像の URL
3. 確かめてから投稿する

```bash
sns-post check                 # 書き方の確認
sns-post run-due               # 下見：何が投稿されるかを表示するだけ
sns-post run-due --publish     # 実際に投稿する
```

4. 結果を確かめる
   - Instagram のアプリで、投稿が出ている
   - 投稿ファイルが `posts/done/` に移り、`results:` に投稿IDが書かれている
   - もう一度 `sns-post run-due --publish` を実行しても、同じ投稿はされない（二重投稿の防止）

予約画面から試すときは、`sns-post web --publish` で起動して、「保存した内容で今すぐ投稿」を使います。

## つまずきやすいところ

| こうなったら | 見直すところ |
|---|---|
| アプリ作成で「Instagram ログイン方式」が選べない | 新しいアプリでは Unified Login だけになっています。`.env` は `IG_LOGIN=unified` のままで大丈夫です |
| 権限から DM（`instagram_manage_messages`）を外せない | ユースケースに必須として入っていて外せません。ツールは DM の API を呼びません |
| 投稿のときに画像のエラーが出る | JPEG か、ログインなしで開ける URL か、`https://` が重なっていないか |
| `check` でタイムゾーンのエラーが出る | `publish_at` の最後に `+09:00` がついているか |
| `run-due` で「時刻が来た投稿はありません」と出る | `publish_at` が未来になっていないか（見本は 2099年です） |
| X の文字数エラーが出る | 日本語は1文字=2文字分で数えます。`x_text` に短い文面を書くか、生成AIの下書きを使う |
